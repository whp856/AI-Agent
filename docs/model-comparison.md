# 模型对比实验说明

## 目的

验证「模型驱动的语义分析相比固定规则具备更强能力」（评审标准 #3），并为后续模型选型提供数据。

## 对比对象

| 方案 | 实现 | 适用场景 |
|---|---|---|
| 规则基线 | `backend/workflow/s3_classify.py::keyword_fallback_topics`（关键词词表 + 统计聚类） | 无模型时的降级兜底 |
| 模型驱动 | `classify_with_llm`（DeepSeek 实时语义归纳） | 正式分析主路径 |

## 对比维度

| 维度 | 指标 |
|---|---|
| 召回 | 模型发现的主题 vs 规则漏掉的主题数量 |
| 语义准确 | 同一问题不同表述（中英混合、口语、讽刺）是否归入同一主题 |
| 适配性 | 换应用/换分析目标后，是否无需改代码 |
| 可解释性 | 主题命名与描述是否贴近用户视角 |
| 置信度 | 模型是否给出可信的置信度与不确定性 |

## 方法

对同一数据集分别运行两种方案，输出对比报告（JSON/Markdown）：

1. 规则基线主题列表 + 模型主题列表；
2. 人工抽查每条评论在两个方案下的归属；
3. 记录模型 token 消耗与耗时。

## 结论模板（每次实验后填写）

```markdown
## 实验：{数据集描述}（{N} 条评论，{语言分布}）

### 规则基线
- 主题数：X（词表命中 Y 条评论）
- 明显缺陷：如"订阅"中英不同写法漏检、讽刺句误判

### 模型驱动（{模型名}）
- 主题数：X，平均置信度：{high/medium/low 分布}
- 发现规则漏掉的主题：{列举}
- 矛盾反馈识别数：{n}

### 结论
- 模型在 {语义聚合/跨语言/主题命名} 上优于规则；
- 规则在 {确定性/可复现} 上优于模型，二者互补；
- 建议：模型做主分析，规则做降级兜底与统计交叉验证（与系统当前设计一致）。
```

## 当前系统设计呼应

- 规则模式产出的主题标记 `confidence_reason: "degraded: rule-based"`；
- 模型模式与规则模式在同一 UI 中可对比查看（降级徽标区分）；
- 统计指标（频次/评分分布）两种模式共用，保证交叉验证基线一致。
